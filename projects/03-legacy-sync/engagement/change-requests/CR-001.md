# CR-001: add the technician completion spreadsheet as a third source

- **Raised:** week 2, by Ray Kowalski (via Luis Ortega)
- **Decision:** deferred to phase 2, after a half-day spike · **Decided by:** Dana Whitfield

## The request

Ray keeps a spreadsheet of on-site completions (`../customer-materials/technician-completions.csv`). His times
are entered on site; WOMS gets updated when someone gets back to a desk. For completion times, the sheet is
more accurate than WOMS. Luis asked whether the sync could use it.

## What the spreadsheet looks like

```
WO #,Site,Completed,Tech,Notes
1006,560 Isham Street,6/17/2024 9:38 AM,JR,
1084,56-30 61 Street,6/17/2024 2:26 PM,JR,replaced
```

No region column. Local times in `M/D/YYYY h:mm AM` with no zone. Addresses in title case. Technician
initials entered inconsistently (`JR` and `jr`).

## Spike: can it be joined to WOMS?

Half a day, throwaway code (`cr-001-spike.py`). Result:

```
$ uv run python engagement/change-requests/cr-001-spike.py
rows=60 wo_id_only: ambiguous=60 unmatched=0 unique=0
wo_id+site: unique=60 unmatched=0
```

- **Work-order number alone: 60 of 60 rows are ambiguous.** Numbers restart per region (Q1), so every number in
  the sheet exists in more than one region.
- **Number plus a normalised site address: 60 of 60 unique** in this sample. But that key relies on a
  free-text address typed on a phone, and one typo makes a record unmatchable, or worse, matched to the
  wrong building.

## Impact analysis

| | Accept now | Defer to phase 2 |
|---|---|---|
| **Scope** | A third source, a fuzzy join on typed addresses, a rule for which completion time wins | None |
| **Schedule** | About one week; the go-live date slips | Go-live unchanged |
| **Risk** | A wrong join closes the wrong building's ticket on the on-call view, which is the exact failure the engagement exists to prevent | None added |
| **Value** | More accurate completion times | Delivered later, on an exact key |

## Decision

**Defer to phase 2**, with one change on Northwind's side: add a Region column to the spreadsheet. With it,
the join becomes `(region, wo_id)`, the same exact key the sync already uses, and the address becomes a check
instead of the key. Phase 2 is then a small, low-risk addition rather than a fuzzy-matching project.
